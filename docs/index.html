Craft Advisor

NeoForge 1.21.1 클라이언트 전용 모드 · JEI 레시피 + Create 클립보드 + Claude AI 제작 조언 · 1차 버전(MVP)

1. 이 모드가 하는 일

채팅에 /ai 기계식 피스톤 만들고 싶어처럼 입력하면 다음이 일어납니다.

🔎 아이템 찾기

JEI에 등록된 아이템 중에서 목표 아이템을 찾고, 그 아이템의 JEI 레시피 화면을 띄웁니다.

🧮 재료 계산

JEI 레시피로 제작 트리를 풀어 인벤토리와 비교하고, 부족한 기본 재료와 필요한 기계를 정확히 계산합니다.

📋 클립보드 기록

손에 든 Create 클립보드에 부족한 재료를 체크박스 목록으로 덧붙입니다. 기존 내용은 지우지 않습니다.

💬 AI 조언

Claude가 계산 결과를 받아 "무엇부터 만들지"를 채팅으로 짧게 조언합니다. 목표가 없는 자유 질문에도 답합니다.

설계 원칙: 계산은 코드, 판단은 AI. AI는 레시피를 잘못 기억하거나 숫자를 틀리는 일이 잦습니다. 그래서 개수와 재료는 항상 코드가 계산하고, AI는 아이템 고르기와 우선순위 설명만 맡습니다. API 키가 없어도 계산과 클립보드 기능은 동작합니다.

2. 작동 방식

  1. /ai 입력 클라이언트
    NeoForge 클라이언트 명령(RegisterClientCommandsEvent)으로 등록돼 있어서 서버로 전송되지 않습니다. 채팅창이 닫힌 뒤 다음 틱에 처리합니다.
  2. 후보 아이템 추리기 코드
    JEI의 전체 아이템을 현재 게임 언어의 이름과 등록 ID로 검색합니다(ItemCandidates). 이름이나 ID가 정확히 일치하면 AI 없이 바로 4단계로 갑니다.
  3. 아이템 고르기 AI · effort low
    후보 목록(최대 40개)과 질문을 Claude에 보내 JSON 형식 {intent, itemId, reason}으로 답을 받습니다. 받은 itemId가 후보에 있는지 코드가 다시 확인합니다. 제작 요청이 아니면 자유 질문(7단계)으로 갑니다.
  4. JEI 레시피 화면 열기 코드
    IRecipesGui.show(OUTPUT focus)로 목표 아이템의 레시피 화면을 엽니다.
  5. 제작 트리 계산 코드
    CraftPlanner가 JEI의 모든 레시피 종류(작업대, 화로, Create 기계 등)를 읽어 트리를 풀고 부족한 재료를 구합니다. 결과는 채팅에 나오고, Create 클립보드를 들고 있으면 클립보드에도 적힙니다.
  6. 조언 AI · effort medium
    계산 결과를 JSON으로 Claude에 넘기고 "숫자를 지어내지 말 것, 5줄 이내"로 조언을 받습니다. AI 응답을 기다리는 동안 게임은 멈추지 않습니다.
  7. 자유 질문 AI · effort medium
    "다음엔 뭐 하지?" 같은 질문에는 최근 대화 6번과 인벤토리 요약을 함께 보내 채팅으로 답합니다.

제작 트리 계산 규칙

규칙내용
레시피 선택인벤토리로 충족되는 입력 칸이 가장 많은 레시피를 고르고, 같으면 JEI 순서를 따릅니다. 지금 따라가는 경로의 아이템을 재료로 쓰는 레시피는 고르지 않습니다(예: 철 블록을 분해해 철 주괴 얻기).
대체 재료(태그)"아무 판자"처럼 여러 아이템이 들어갈 수 있는 칸은 그중 하나라도 있으면 충족된 것으로 봅니다. 없으면 JEI가 첫 번째로 보여 주는 아이템을 풀어 나갑니다.
멈추는 조건인벤토리로 충족되는 경우, 레시피가 없는 경우(광물·원목 등), 순환하는 경우, 깊이 8단계에 도달한 경우에는 더 풀지 않고 "부족한 기본 재료"로 적습니다.
개수필요 개수를 레시피 출력 개수로 나눠 올림합니다. 남는 결과물(원목 1 → 판자 4)은 이후 재료에 다시 씁니다. 원본 인벤토리는 바꾸지 않습니다.

Create 클립보드 쓰기

클라이언트 모드는 서버의 아이템을 직접 바꿀 수 없습니다. 그래서 Create의 클립보드 화면이 내용을 저장할 때 쓰는 요청(ClipboardEditPacket)을 같은 형식으로 서버에 보냅니다. Create가 깔린 서버라면 내 모드를 서버에 설치하지 않아도 반영됩니다.

  • Create 6.0.10 ~ 6.1 미만만 지원합니다. 클립보드 데이터 형식이 6.0.7에서 바뀌었기 때문입니다.
  • 항목에 클릭 이벤트가 하나라도 있으면 서버가 클립보드 내용을 지워 버리므로, 항목은 항상 일반 텍스트로만 만듭니다.
  • 한 페이지에 머리말 1줄과 재료 14개까지 적고, 클립보드 전체는 51페이지를 넘지 않게 합니다.

├─ CraftAdvisor.java          모드 진입점, 설정 등록

├─ planner/                   Minecraft에 의존하지 않는 순수 Java (단위 테스트 대상)
│  ├─ CraftPlanner.java       제작 트리 계산
│  ├─ CraftPlan.java          결과: 제작 단계 · 부족 재료 · 기계

├─ jei/
│  ├─ CraftAdvisorJeiPlugin   JEI 런타임 보관

│  ├─ ItemCandidates          질문 → 후보 아이템 검색
│  └─ Items                   아이템 ↔ ItemKey, 인벤토리 집계
├─ clipboard/
│  ├─ MaterialOutput          채팅 출력 + (Create 있으면) 클립보드
│  ├─ CreateClipboardWriter   Create 클립보드에 페이지 덧붙이기

├─ ai/
│  ├─ AiProvider              AI 인터페이스 (다른 제공자 확장 지점)

│  └─ Prompts, ItemPick, AiException
└─ chat/ChatOut.java          채팅 출력 도우미 (로컬에만 표시)

5. 집에서 확인하기

준비

git clone https://github.com/Oksyusu/craft-advisor.git
cd craft-advisor
gradlew.bat build        # 첫 빌드는 Minecraft 파일을 받느라 10~20분 걸릴 수 있음
gradlew.bat runClient    # 또는 IntelliJ: Gradle 탭 → Tasks → mod development → runClient

JDK 21이 필요합니다. IntelliJ에서 열 때는 Settings → Build Tools → Gradle → Gradle JVM을 21로 맞추세요.

API 키 넣기

게임 안의 모드 → Craft Advisor → 설정에서 넣거나, run/config/craftadvisor-client.toml의 apiKey를 고칩니다. run/ 폴더는 .gitignore에 들어 있어서 키가 저장소에 올라가지 않습니다.

확인 목록 (크리에이티브 월드)

  • 모드 목록에 JEI, Create, Craft Advisor가 보인다
  • /ai minecraft:piston → JEI 레시피 화면이 열리고 채팅에 부족한 재료가 나온다
  • Create 클립보드를 들고 /ai create:mechanical_piston → 클립보드에 페이지가 덧붙고, 다시 접속해도 남아 있다
  • 키를 넣고 /ai 기계식 피스톤 만들고 싶어 → "찾는 중" → JEI 화면 → 재료 목록 → 조언 순서로 나온다
  • /ai 다음엔 뭐 하지? → 채팅으로 답한다
  • 키를 틀리게 넣으면 안내 문구가 나오고, run/logs/latest.log에 키가 찍히지 않는다
  • AI 응답을 기다리는 동안 게임이 멈추지 않는다
  • build.gradle에서 Create의 localRuntime 줄을 주석 처리하고 실행해도 정상 로드된다

아직 확인하지 못한 점

  • 게임 안에서는 아직 한 번도 실행하지 않았습니다. 빌드와 단위 테스트만 통과한 상태입니다.
  • 클립보드 항목의 개수가 글자("x4")와 아이콘 옆에 두 번 보일 수 있습니다.
  • JEI가 내부 설정 라이브러리(mezz_config)를 찾지 못해 실행되지 않으면, build.gradle에 localRuntime "net.mezzdev.config:mezz_config-1.21.1-neoforge:0.6.10"을 추가합니다.
  • 프롬프트 캐싱을 설정했지만, 지금 시스템 프롬프트가 짧아서 실제로는 캐시가 걸리지 않을 가능성이 높습니다.
