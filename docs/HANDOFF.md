## 사양을 나눌 때 주의할 의존 관계
- **3번이 2·4번보다 먼저입니다.** `ItemKey`를 JEI 고유 ID 기준으로 바꾸는 작업이 3번에 들어 있는데, 2번(도구 결과의 아이템 식별)과 4번(목표 합산)이 모두 이 식별 방식에 의존합니다.
- **1번과 2번은 함께 설계해야 합니다.** 도구 호출 방식에서는 `get_inventory` 결과도 Claude로 나갑니다. 미리보기와 공유 항목 선택이 도구 결과에도 적용되어야 합니다.
- **2번과 5번:** 도구 호출은 제공자마다 형식이 다릅니다(Anthropic과 OpenAI 호환은 도구 형식이 다르고, Ollama는 불안정할 수 있음). 2번 사양에서는 `AiProvider` 인터페이스에 도구 호출을 어떻게 표현할지 정해 두는 것이 좋습니다.
- **7번의 클릭 이벤트는 채팅에만** 답니다(클립보드 금지 규칙과 충돌).
- **6번은 별도 딥 인터뷰가 필요합니다.** 대상 기계, RPM, 처리 시간 데이터를 어디서 얻을지가 아직 정해지지 않았습니다.

## 작업 환경 메모
- `gradlew` 실행은 이번 세션 후반부터 허용됐지만, 다른 세션에서는 자동 모드 검사에 막힐 수 있습니다. 막히면 settings에 `PowerShell(.\gradlew.bat:*)` 허용 규칙을 추가합니다.
- GitHub 저장소 생성이나 공개 전환 같은 외부 작업은 자동 모드 검사가 막을 수 있습니다. 그때는 사용자가 `!` 접두어로 직접 실행합니다.
- 이 PC의 GateGuard 훅은 파일을 처음 만들거나 고칠 때 근거 설명을 요구합니다(호출자, 기존 파일 여부, 사용자 지시 원문).
- 커밋 메시지는 `<type>: <설명>` 형식에 `Co-Authored-By` 줄을 붙입니다. PowerShell에서 메시지 파일을 쓸 때는 BOM 없는 UTF-8로 써야 합니다.
