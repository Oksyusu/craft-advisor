# 사양서 06: 공장 비율 계산

> 상태: **인터뷰 전 초안.** HANDOFF의 결정대로 이 기능은 **별도 딥 인터뷰를 거친 뒤** 사양을 확정한다. 이 문서는 인터뷰 준비 자료이며, 아래 범위와 완료 기준은 가안이다.

## 메타데이터
- 작성일: 2026-11-13
- 출처: `docs/feature-research.md` 6절 (원본: GTCalcBoard), 1차 사양서 "1차 버전에서 하지 않는 것"
- 작업량 추정: 어려움
- 선행 사양: 03(재료 키, 레시피 종류 정보), 04(여러 목표 합산)를 쓰면 좋다. 필수는 아님
- 배정된 한계: "공장 비율 계산 없음"
- 시점: 2차 버전

## 목표 (가안)
플레이어가 "분당 X개"처럼 목표 생산량을 말하면, 코드가 필요한 **기계 종류와 대수**, 상류 재료의 분당 소모량을 계산하고, AI는 배치와 병목을 설명한다. 결과는 채팅과 Create 클립보드("기계 N대" 목록)로 보여 준다.

## 이미 정해진 것
- 계산은 코드, 판단은 AI. 비율 계산은 결정적인 수학이므로 전부 코드가 한다.
- 클라이언트 전용. 서버 설치가 필요한 데이터는 쓰지 않는다.
- 기계 대수는 정수로 올림한다(GTCalcBoard와 같음).
- 클립보드는 덧붙이기, 클릭 이벤트 금지.

## 어려운 이유
1. **처리 시간 데이터:** JEI는 레시피 처리 시간을 공통 방식으로 주지 않는다.
2. **Create의 회전 속도:** 같은 레시피라도 RPM에 따라 처리 속도가 달라진다. 기계마다 공식이 다르다.
3. **기계 종류마다 처리 방식이 다르다:** 한 번에 하나(분쇄 바퀴는 아이템 묶음 단위), 분지(Basin) 단위, 컨베이어 위 연속 처리(프레스, 선풍기) 등.

## 데이터 출처 후보 (인터뷰 전 조사 메모, 미검증)
| 후보 | 내용 | 확인할 것 |
|---|---|---|
| Create 레시피 객체 | Create의 처리 레시피는 `processingDuration`을 가진 종류가 있다(분쇄, 맷돌 등) | 1.21.1 클라이언트에 레시피가 동기화되어 있어 클라이언트에서 읽을 수 있는지, 어느 종류에 값이 있는지 |
| Create 소스의 속도 공식 | 기계별 RPM → 처리 속도 식 | Create 6.0.x 소스에서 기계별 식을 옮겨 적을 수 있는지(라이선스 확인 포함) |
| 사용자 입력 | `/ai rate …`에서 RPM이나 처리 시간을 직접 지정 | 입력이 번거로워지지 않는지 |
| 바닐라 | 화로 200틱, 용광로·훈연기 100틱 등 고정값 | 연료 소모까지 넣을지 |

## 인터뷰에서 정할 질문
1. **대상 기계:** Create 기계 몇 종만으로 시작할까? (후보: 분쇄 바퀴, 맷돌, 기계식 프레스, 기계식 믹서, 선풍기 처리, 바닐라 화로) 다른 모드(Thermal, Mekanism 등)는?
2. **입력 형태:** "분당 X개 목표"만? "기계 N대가 있으면 분당 몇 개"(역방향)도?
3. **RPM:** 기본값 하나(예: 64 RPM)로 고정? 기계별로 지정? 응력(SU) 계산까지?
4. **범위의 깊이:** 목표 아이템의 직속 레시피 한 단계만? 03·04처럼 트리 전체를 풀어 상류 체인 전체?
5. **병목 기준 역산:** "이 기계가 2대뿐이면 전체 규모는?"(GTCalcBoard의 Master Anchor)이 필요한가?
6. **출력:** 채팅 표, 클립보드 "기계 N대" 목록, 둘 다?
7. **처리 시간을 모르는 레시피:** 계산에서 빼고 표시? 사용자에게 값을 물음? AI에게 추정시킴(원칙상 비추천)?
8. **1차 범위의 성공 장면:** "`/ai 분당 안산암 합금 60개` → 믹서 N대, 프레스 M대, 분당 재료 소모량" 같은 한 장면으로 정할 수 있는가?

## 가안 범위 (인터뷰 결과로 바뀜)
- `/ai rate <아이템> <분당 개수>` 명령
- 대상: 바닐라 화로 계열 + Create 기계 3~4종, 기본 RPM 하나
- 계산기: 순수 Java `RateCalculator`. 입력은 레시피(출력 개수, 처리 시간 틱, 기계 종류), 결과는 기계별 대수(올림)와 재료별 분당 소모량
- 처리 시간을 모르는 레시피는 "처리 시간 모름"으로 표시하고 대수 계산에서 뺀다

## 가안 완료 기준 (인터뷰 후 확정)
- [ ] 1. 단위 테스트: 처리 시간·출력 개수·목표 분당량이 주어지면 기계 대수가 올림으로 맞다.
- [ ] 2. 단위 테스트: 두 단계 체인에서 상류 기계 대수가 하류 소모량 기준으로 계산된다.
- [ ] 3. 단위 테스트: 처리 시간을 모르는 단계가 있으면 그 단계만 "모름"으로 나오고 나머지는 계산된다.
- [ ] 4. 게임 확인: 성공 장면 하나(인터뷰에서 정함)가 채팅과 클립보드에 나온다.
