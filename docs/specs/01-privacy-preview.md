# 사양서 01: 보낼 정보 미리보기 + 공유 항목 선택

> 상태: **초안 (승인 대기)**. 승인 전에는 구현하지 않는다.

## 메타데이터
- 작성일: 2026-11-13
- 출처: `docs/feature-research.md` 1절 (원본: MCAI, Packwise)
- 작업량 추정: 쉬움
- 선행 사양: 없음
- **함께 설계:** 02(도구 호출). 도구 결과도 Claude로 나가므로 이 사양의 공유 규칙이 도구에도 적용된다.
- 배정된 한계: "자유 질문 때 인벤토리 요약을 묻지 않고 보냄"

## 목표
플레이어가 **무엇이 외부 AI로 나가는지 알고 고를 수 있게** 한다.
1. 처음 AI 호출이 필요할 때, 보낼 정보와 받는 곳을 채팅으로 알리고 동의를 받는다.
2. 설정으로 공유 항목(인벤토리, 대화 기록)을 끌 수 있다.
3. `/ai preview <질문>`으로 실제 요청 내용을 보내지 않고 확인한다.

## 현재 상태 (코드 기준)
| 나가는 정보 | 위치 | 현재 동작 |
|---|---|---|
| 질문 원문 | `ClaudeProvider.pickItem/advise/chat` | 항상 보냄 |
| JEI 후보 목록(id, 이름 최대 40개) | `AdvisorFlow.start` | 항상 보냄 |
| 계산 결과 JSON(목표, 기계, 제작 단계 30개, 부족 재료) | `AdvisorFlow.planJson` | 항상 보냄. **부족 개수에서 인벤토리가 간접적으로 드러남** |
| 인벤토리 요약(많은 순 40종) | `AdvisorFlow.inventorySummary` | 자유 질문 때 **묻지 않고** 보냄 |
| 최근 대화(최대 12턴) | `AdvisorFlow.HISTORY` | 자유 질문 때 보냄 |
| API 키 | HTTP 헤더 `x-api-key` | 인증용으로만 전송, 본문에는 없음 |

플레이어 이름, UUID, 서버 주소, 좌표, 시드, 채팅 기록은 지금도 보내지 않는다. 아이템 이름은 기본 이름(`new ItemStack(item)`)을 쓰므로 모루로 바꾼 이름도 나가지 않는다. **이 성질을 유지하고 테스트로 고정한다.**

## 범위
### 1. 공유 설정 (`ClientConfig`)
| 키 | 기본값 | 의미 |
|---|---|---|
| `shareInventory` | `true` | 끄면 인벤토리 정보가 AI로 나가지 않는다(아래 규칙) |
| `shareHistory` | `true` | 끄면 자유 질문에 이전 대화를 붙이지 않는다 |
| `consentedHost` | `""` | 동의한 AI 주소의 호스트(예: `api.anthropic.com`). 비어 있거나 현재 호스트와 다르면 다시 동의를 받는다 |

**`shareInventory = false`일 때 규칙**
- 자유 질문: 인벤토리 요약 대신 `"not shared"`를 보낸다.
- 조언(`advise`): AI에게 보내는 계산 결과는 **빈 인벤토리 기준**으로 다시 계산한 값(전체 필요량)을 쓴다. 채팅과 클립보드에는 지금처럼 실제 인벤토리 기준 결과를 보여 준다.
- 조언 프롬프트에 "counts are totals; inventory not shared"를 덧붙여 AI가 "부족하다"고 단정하지 않게 한다.
- 02의 `get_inventory` 도구는 목록에서 빠지고, `compute_missing` 도구는 빈 인벤토리 기준으로 계산한다.

### 2. 처음 한 번 동의
- AI 호출이 필요한 순간(정확한 이름 검색으로 끝나지 않는 경우)에 `consentedHost`가 현재 호스트와 다르면 **호출하지 않고** 안내를 띄운다.
  - 받는 곳: 호스트 이름
  - 보내는 것: 질문, JEI 아이템 후보, 계산 결과, (설정이 켜져 있으면) 인벤토리 요약·최근 대화
  - 보내지 않는 것: 플레이어 이름, 서버 주소, 좌표, 채팅, 바꾼 아이템 이름
  - 설정 파일 위치와 `/ai consent`, `/ai preview` 안내
- `/ai consent`: `consentedHost`를 현재 호스트로 저장하고(`ConfigValue.set` 후 저장), **보류했던 질문을 이어서 실행한다.** 보류 질문은 메모리에 하나만 둔다.
- 동의 전에도 정확한 이름·ID 검색, 계산, JEI 화면, 클립보드는 동작한다(API 키가 없을 때와 같은 범위).
- 05에서 `localhost`·`127.0.0.1` 같은 로컬 주소는 동의를 건너뛰도록 확장한다(외부로 나가지 않음).

### 3. `/ai preview <질문>`
- `/ai <질문>`과 같은 경로를 따라가되, **HTTP 요청 직전에 멈추고** 보낼 내용을 채팅에 보여 준다.
  - 어느 경로인지(정확한 검색으로 끝남 / 아이템 고르기 / 조언 / 자유 질문)
  - 받는 곳 호스트, 모델
  - 사용자 메시지 본문(섹션별로, 긴 부분은 앞 몇 줄과 전체 글자 수)
  - 02 이후: 제공되는 도구 목록과 꺼진 도구
- JEI 화면 열기와 클립보드 쓰기는 하지 않는다(미리보기는 부작용 없음).
- 미리보기는 동의로 치지 않는다.
- 도구 호출 방식에서는 첫 요청만 미리 볼 수 있다. 이후 도구 결과는 AI가 어떤 도구를 부를지에 달려 있으므로 "도구 결과는 위 공유 설정에 따라 걸러진다"는 문구로 대신한다.

### 4. 구조 변경
- 요청 본문을 만드는 부분을 HTTP 전송과 분리한다: `OutgoingRequest`(호스트, 경로 이름, 사용자 메시지 섹션 목록, 도구 목록)를 만드는 순수 Java 코드 → 전송과 미리보기가 같은 값을 쓴다.
- 이 코드는 플레이어 이름·서버 주소·좌표를 **입력으로 받지 않는다**(구조로 보장).

## 범위에서 빼는 것
- 요청마다 확인(Packwise 방식). 혼자 쓰는 용도에서는 번거롭다. 필요하면 나중에 `confirmEachRequest` 설정으로 추가
- 게임 안 설정 화면. 설정은 toml 파일과 `/ai consent`로만 다룬다
- 시스템 프롬프트 전문 미리보기(고정 문구라서 저장소에서 확인 가능)

## 명령어 예약어
`/ai preview`, `/ai consent`는 Brigadier 리터럴이라 `/ai <자유 질문>`보다 먼저 잡힌다. 질문이 영어 단어 `preview`·`consent`로 시작하면 하위 명령으로 처리된다. 다른 사양의 예약어: `show`(07), `add`·`list`·`remove`·`clear`(04). 예약어 목록은 `/ai`만 입력했을 때 도움말로 보여 준다.

## 완료 기준
- [ ] 1. 단위 테스트: `shareInventory=false`이면 `OutgoingRequest`의 어느 섹션에도 인벤토리 아이템 이름·개수가 들어가지 않는다. 조언 요청의 계산 결과는 빈 인벤토리 기준 값과 같다.
- [ ] 2. 단위 테스트: `shareHistory=false`이면 자유 질문 메시지에 이전 대화가 없다.
- [ ] 3. 단위 테스트: 요청 본문에 API 키 문자열이 없다(가짜 키로 확인).
- [ ] 4. 게임 확인: 설정을 지운 상태로 `/ai 다음엔 뭐 하지?` → 안내가 뜨고 HTTP 호출이 없다(로그로 확인). `/ai consent` → 같은 질문의 답이 나온다. 재접속 후에는 안내가 다시 뜨지 않는다.
- [ ] 5. 게임 확인: `/ai preview 기계식 피스톤 만들고 싶어` → 경로와 보낼 내용이 채팅에 나오고, JEI 화면·클립보드·HTTP 호출이 일어나지 않는다.
- [ ] 6. 동의 전에도 `/ai create:mechanical_piston`은 JEI 화면과 부족 재료를 보여 준다.

## 결정 필요 (추천안 먼저)
1. **`shareInventory` 기본값:** `true` 추천(혼자 쓰고, 동의 안내에서 알림). Packwise처럼 `false`로 하면 조언 품질이 기본적으로 떨어진다.
2. **동의 후 보류 질문 자동 실행:** 실행 추천. 아니면 다시 입력하게 한다.
