# 사양서 07: 재료 이름 클릭으로 JEI 이동 + 인벤토리 강조

> 상태: **초안 (승인 대기)**. 승인 전에는 구현하지 않는다.

## 메타데이터
- 작성일: 2026-11-13
- 출처: `docs/feature-research.md` 7절 (원본: MCAI)
- 작업량 추정: 쉬움(1단계), 중간(2단계)
- 선행 사양: 없음. 03 이후면 비아이템 재료도 열 수 있고, 04 이후면 목록 줄에도 적용한다
- 단계: **1단계 클릭**을 먼저 하고, **2단계 인벤토리 강조**는 나중에 한다(연구 문서 권장)

## 목표
채팅의 부족 재료 목록에서 재료 이름을 누르면 그 재료의 JEI 레시피 화면이 열린다. "다음엔 이걸 만들어야지"로 바로 이어진다.

## 고정 결정
- **클릭 이벤트는 채팅에만 단다.** Create 클립보드 항목에 클릭 이벤트가 있으면 서버가 클립보드 내용을 지운다(`CreateClipboardWriter` 주석).

## 현재 상태 (코드 기준)
- `ChatOut.plan`: 목표, 기계(이름을 쉼표로 이은 **문자열 하나**), 부족 재료 줄을 `Component.translatable`로 보낸다. 클릭·마우스 올림 없음.
- `/ai <아이템 ID>`는 정확한 ID 검색으로 계산까지 하므로, 클릭에 그대로 쓰면 **계산을 다시 하고 손에 든 클립보드에 페이지를 덧붙이고 AI 조언을 부른다**(원치 않는 부작용과 비용).

## 범위: 1단계 클릭
### 1. 새 하위 명령 `/ai show <uid>`
- 그 재료의 JEI 레시피 화면(출력 기준)만 연다. 계산, 클립보드, AI 호출은 하지 않는다.
- 레시피가 없는 재료(광석, 원목 등)는 용도 화면(입력 기준)을 연다. 둘 다 없으면 "JEI에 레시피가 없어요"를 보여 준다.
- `uid`는 03 이전에는 등록 ID, 03 이후에는 03의 키 문자열(`fluid:` 등 접두어 포함).
- 지금 `AiCommand`처럼 `Minecraft.tell`로 채팅 화면이 닫힌 뒤 연다.

### 2. 클릭을 다는 곳
| 채팅 줄 | 클릭 | 마우스 올림 문구 |
|---|---|---|
| 목표 | `/ai show <목표>` | "클릭: 레시피 보기" |
| 필요한 기계(이름마다 따로) | `/ai show <기계>` | 같음 |
| 부족 재료 줄 | `/ai show <재료>` | 같음. 04 이후에는 "목표 1: 4개, 목표 2: 6개" 기여 내역을 덧붙임 |
| 03의 "고른 대안" 줄 | `/ai show <고른 재료>` | 같음 |
| 05의 오프라인 후보 목록 | `/ai show <후보>` | 같음 |

- `ClickEvent.Action.RUN_COMMAND`와 `HoverEvent.Action.SHOW_TEXT`를 쓴다. 클릭 가능한 이름은 밑줄로 표시한다.
- 기계 줄은 이름별 컴포넌트로 이어 붙이도록 `joinNames`를 바꾼다.
- AI가 쓴 조언 문장 안의 아이템 이름에는 달지 않는다(자유 문장에서 이름을 안정적으로 찾을 수 없음).
- 클립보드 줄을 만드는 코드(`CreateClipboardWriter.Line`)는 바꾸지 않는다.

### 명령어 예약어
`show`는 리터럴 하위 명령이다. 전체 예약어는 01 참고.

## 범위: 2단계 인벤토리 강조 (나중에)
- 마지막 계산에서 **인벤토리에서 꺼내 쓴 재료**가 들어 있는 칸을 인벤토리·상자 화면에서 반투명 색으로 강조한다.
- 계산기가 지금은 "인벤토리에서 쓴 양"을 기록하지 않으므로 `CraftPlan`에 `used: Map<키, 개수>`를 추가한다(순수 Java, 테스트 가능).
- 화면 그리기: NeoForge `ContainerScreenEvent.Render.Foreground`에서 해당 칸 위에 사각형을 그린다.
- 끄기: `highlightInventory` 설정(기본 켬), 새 계산을 하면 대상이 바뀌고, 04의 `/ai clear` 때 지운다.

## 범위에서 빼는 것
- 레시피 트리 그래프 화면(MCAI의 가지 모양 화면)
- AI 조언 문장 안의 이름 클릭

## 완료 기준
### 1단계
- [ ] 1. 단위 테스트(또는 기존 `ClipboardPagesTest` 옆에 회귀 테스트): 클립보드 줄 문자열 생성 경로에 클릭 이벤트가 들어가지 않는다. Minecraft 클래스 없이 테스트하기 어렵다면 이 기준은 게임 확인 4번으로 대신한다.
- [ ] 2. 게임 확인: `/ai 기계식 피스톤 만들고 싶어` 후 채팅의 부족 재료 이름을 누르면 그 재료의 JEI 레시피 화면이 열린다. 클립보드에 페이지가 늘지 않고, AI 호출 로그가 없다.
- [ ] 3. 게임 확인: 광석처럼 레시피가 없는 재료를 누르면 용도 화면이 열린다.
- [ ] 4. 게임 확인: 클립보드를 들고 계산한 뒤 클립보드를 열어도 내용이 지워지지 않는다(클릭 이벤트가 클립보드로 새지 않음).
- [ ] 5. 게임 확인: 멀티 서버에서 클릭해도 서버로 명령이 가지 않는다(서버 로그 또는 "알 수 없는 명령" 오류가 없음으로 확인).

### 2단계
- [ ] 6. 단위 테스트: `CraftPlan.used`의 합이 인벤토리에서 실제로 줄어든 양과 같다.
- [ ] 7. 게임 확인: 계산 후 인벤토리를 열면 쓰인 재료 칸이 강조되고, `highlightInventory=false`면 강조가 없다.

## 위험
- **R1. 클릭 명령 가로채기:** 1.21.1에서 채팅 클릭(`RUN_COMMAND`)으로 실행된 명령이 NeoForge의 클라이언트 명령 처리로 들어가는지 게임에서 먼저 확인한다(연구 문서는 그렇다고 하지만 코드로 확인하지 않음). 안 되면 클릭 대신 `SUGGEST_COMMAND`(입력창에 채워 주기)로 바꾼다.
- **R2. 채팅 화면과 JEI 화면 순서:** 클릭은 채팅 화면이 열린 상태에서 일어난다. `tell`로 미룬 뒤 JEI 화면이 채팅 화면을 대신하는지, JEI 화면을 닫으면 어디로 돌아가는지 확인한다.

## 결정 필요 (추천안 먼저)
1. **클릭 명령:** `/ai show <uid>` 새 하위 명령 추천. `/ai <uid>`를 쓰면 구현은 더 작지만 클릭마다 클립보드에 페이지가 쌓이고 AI 비용이 든다.
2. **2단계 진행 여부:** 1단계를 집에서 확인한 뒤 결정 추천.
