## 목표
플레이어가 채팅에 `/ai <자연어>`를 입력하면 다음이 일어난다.
1. AI가 JEI 아이템 목록에서 목표 아이템을 찾는다.
2. 그 아이템의 JEI 레시피 화면을 띄운다.
3. 모드 코드가 JEI 레시피로 제작 트리를 풀어 인벤토리와 비교하고, 부족한 기본 재료를 정확히 계산한다.
4. 계산 결과를 손에 든 Create 클립보드에 체크박스 목록으로 적는다. 클립보드가 없으면 채팅으로 보여 준다.
5. AI가 그 결과를 바탕으로 다음에 할 일과 더 나은 레시피를 채팅으로 짧게 조언한다.

목표가 없는 자유 질문(예: "다음엔 뭐 하지?")도 같은 명령으로 받아 채팅으로 답한다.

## 제약
- **버전:** Minecraft 1.21.1, NeoForge 21.1.x (MDK 기준 21.1.265), Java 21
- **설치 위치:** 클라이언트 전용 모드. 서버에 설치하지 않고도 멀티 서버에서 동작하는 것을 목표로 한다.
- **의존성:** JEI는 필수(없으면 로드 실패), Create는 선택(없으면 클립보드 기능만 꺼지고 채팅으로 대신 보여 줌)
- **대상 환경:** 특정 모드팩에 묶이지 않고, JEI가 아는 레시피만 쓴다. 퀘스트북은 읽지 않는다.
- **AI:** 1차 버전은 Claude API 하나만, 플레이어 자신의 API 키를 쓴다. 다른 제공자는 나중에 붙일 수 있게 호출 부분을 인터페이스로 분리한다.
- **역할 분담:** 제작 트리, 개수, 부족한 재료는 코드가 계산한다(결정적이고 테스트 가능). AI는 아이템 찾기, 우선순위 판단, 설명, 다른 레시피 제안만 한다. AI가 계산한 숫자를 그대로 쓰지 않는다.
- **API 키 보안:** 키는 게임 설정 폴더의 클라이언트 설정 파일에만 두고, 저장소에 커밋하지 않으며, 로그와 채팅에 출력하지 않는다. 나중에 친구나 Git에 공유할 것을 전제로 한다.
- **채팅 내용 보호:** `/ai`는 클라이언트 전용 명령이라 서버로 전송되지 않는다.
- **게임 멈춤 방지:** AI 호출은 게임을 그리는 스레드 밖에서 비동기로 하고, 결과는 게임 메인 스레드로 돌려받는다.
- **키가 없을 때:** 키가 없거나 호출에 실패해도 3·4단계(코드 계산과 클립보드 기록)는 동작한다. 아이템 찾기는 키가 없으면 정확한 이름이나 ID로만 검색한다.

### 제작 트리 규칙
- 레시피가 여러 개면, 지금 인벤토리로 더 많이 충족되는 레시피를 고른다. 같으면 JEI가 보여 주는 순서를 따른다.
- 태그 재료(예: 아무 판자)는 해당하는 아이템을 하나라도 가지고 있으면 충족된 것으로 본다.
- 다음 경우에는 더 풀지 않고 "부족한 기본 재료"로 적는다: 인벤토리에 있는 아이템, 레시피가 없는 아이템, 순환이 생기는 아이템, 깊이 8단계에 도달한 아이템.
- 개수는 레시피의 출력 개수를 반영해 올림으로 계산한다.

## 1차 버전에서 하지 않는 것
- 공장 비율(분당 생산량, 기계 대수) 계산 → 2차 버전
- 전용 GUI 화면과 화면 구석 표시 → 채팅과 JEI 화면으로 대신함
- OpenAI, Gemini, 로컬 AI 지원 → 확장 구조만 마련해 둠
- 중계 서버 운영
- FTB Quests 같은 퀘스트북 연동
- 서버 쪽 모드 설치가 필요한 기능

## 완료 기준
- [ ] 1. `gradlew build`가 성공하고, `runClient`로 실행하면 JEI와 Create가 함께 로드된 개발 클라이언트가 뜬다.
- [ ] 2. `/ai 기계식 피스톤 만들고 싶어`를 입력하면 Create의 기계식 피스톤 JEI 레시피 화면이 열린다. 이 내용은 채팅으로 서버에 전송되지 않는다.
- [ ] 3. 제작 트리 계산기 단위 테스트: 가짜 레시피 데이터(바닐라 레시피 몇 개, Create 레시피 몇 개, 태그 재료, 순환 레시피, 출력 개수가 2 이상인 레시피, 9단계 이상 깊은 트리)에 대해 예상한 부족 재료 목록과 정확히 같은 결과를 낸다.
- [ ] 4. Create 클립보드를 손에 들고 실행하면 부족한 재료가 체크박스 목록으로 적히고, 다시 접속해도 내용이 남아 있다. 클립보드가 없으면 같은 목록이 채팅에 나온다.
- [ ] 5. AI 조언이 채팅에 나오고, 그 안의 숫자는 코드 계산 결과와 어긋나지 않는다. 계산 결과를 AI에게 넘겨주고 숫자를 지어내지 말라고 지시한다.
- [ ] 6. `/ai 다음엔 뭐 하지?` 같은 자유 질문에 채팅으로 답한다.
- [ ] 7. API 키가 없거나 틀리면 이해하기 쉬운 오류 문구를 채팅에 보여 주고, 3·4번(계산과 클립보드)은 계속 동작한다. 키는 로그와 채팅에 나타나지 않는다.
- [ ] 8. AI 응답을 기다리는 동안 게임이 멈추지 않는다.
- [ ] 9. Create를 빼고 실행해도 모드가 정상 로드되고, 클립보드 기능만 꺼진다.

### 구조 제안 (구현 계획 단계에서 확정)
- `command`: `RegisterClientCommandsEvent`로 `/ai` 클라이언트 명령을 등록
- `jei`: `@JeiPlugin` / `IModPlugin`. `onRuntimeAvailable`에서 `IJeiRuntime`을 받아 레시피와 아이템을 조회하고 `IRecipesGui.show(focus)`로 레시피 화면을 엶
- `planner`: 제작 트리 계산기. 레시피를 읽는 부분을 인터페이스로 분리해서 JEI 연결 코드와 테스트용 가짜 데이터를 갈아 끼울 수 있게 함
- `ai`: `AiProvider` 인터페이스와 `ClaudeProvider` 구현. 아이템 찾기는 코드가 이름 검색으로 후보를 추린 뒤 AI가 후보 중 하나를 고르는 구조(정해진 형식의 응답). 조언은 계산 결과를 JSON으로 넘겨서 받음
- `clipboard`: Create가 있을 때만 불러오는 연결 코드. Create 클립보드 데이터 형식에 맞춰 내용을 쓰고, Create가 쓰는 서버 전송 방식으로 반영함
- `config`: NeoForge의 클라이언트 설정 파일에 API 키, 모델, 최대 토큰을 둠. 기본 모델은 응답이 빠른 Claude Haiku 계열에서 구현할 때 정함

### 위험 항목 (구현 전에 먼저 확인)
- **R1. Create 클립보드 쓰기:** 클라이언트에서 손에 든 클립보드의 내용을 바꾸려면 Create가 쓰는 서버 전송 방식(클립보드 편집 요청)을 재사용해야 할 가능성이 높다. Create 1.21.1의 실제 클래스와 데이터 형식을 확인하고, 클라이언트 전용으로 서버에 반영되는지 확인한다. 안 되면 채팅 목록으로 대신하거나 Create의 클립보드 화면을 미리 채워서 여는 방식을 검토한다.
- **R2. 한국어 이름 검색:** 아이템 찾기 후보를 만들 때 현재 게임 언어의 표시 이름과 등록 ID를 함께 검색해야 한다.
- **R3. JEI 레시피 종류의 다양성:** Create 기계 레시피(압착, 혼합 등)도 JEI에서 공통 방식으로 재료와 결과를 읽을 수 있는지 확인한다.
