# 도입 후보 기능 7가지: 원본 모드와 도입 이유

조사일: 2026-11-13 · 방법: 웹 출처 21곳 조사, 주장 25개 반대 검증(반박 0개)

> **읽기 전에:** 근거 대부분은 각 모드 개발자가 쓴 CurseForge·Modrinth 설명입니다. 기능이 **있다**는 것은 확인했지만 **얼마나 잘 동작하는지**는 검증하지 않았습니다. 버전, 다운로드 수, 날짜는 조사일 기준이라 금방 바뀔 수 있습니다. "작업량"은 추정이고 측정한 값이 아닙니다.

## 요약

| 순위 | 기능 | 원본 모드 | 작업량 | 해결하는 우리 문제 |
|---|---|---|---|---|
| 1 | 보낼 정보 미리보기 + 공유 항목 선택 | MCAI, Packwise | 쉬움 | 외부 API로 게임 정보를 보내는 데 대한 불안 |
| 2 | 도구 호출 방식 (LLM이 JEI 조회 도구를 직접 호출) | Viper LLM | 중간 | 자유 질문에서 레시피를 지어냄, 후보 검색 실패(예: "아이언 비") |
| 3 | 대체 재료 선택 + 레시피 선호 규칙 | JEI unofficial | 중간 | 같은 ID의 변형이 하나로 합쳐짐, 레시피 선택 고정 |
| 4 | 여러 목표를 하나의 목록으로 | ETT (EMI Tree Tabs) | 중간 | 목표마다 따로 계산해서 재고를 두 번 셈 |
| 5 | AI 제공자 확장 (OpenAI 호환, Ollama, 오프라인) | PAIA | 중간 | Claude 키가 없는 친구는 AI 기능을 못 씀 |
| 6 | 공장 비율 계산 | GTCalcBoard | 어려움 | 2차 버전으로 미뤄 둔 기능 |
| 7 | 재료 이름 클릭으로 JEI 이동 + 인벤토리 강조 | MCAI | 쉬움 | 채팅 목록에서 다음 행동으로 이어지지 않음 |

## 1. 보낼 정보 미리보기 + 공유 항목 선택

**원본 모드**
- [MCAI (MC Ai Intergration)](https://www.curseforge.com/minecraft/mc-mods/mcai-mc-ai-intergration): NeoForge 1.21.1 클라이언트 전용
- [Packwise AI Assistant](https://www.curseforge.com/minecraft/mc-mods/ai-minecraft-assistant): Fabric/NeoForge 1.21.1, v0.1.0

**원본에서의 역할**
- **MCAI:** "share whitelist" 설정으로 인벤토리, 플레이어 상태 같은 항목 중 무엇을 AI에 보낼지 고릅니다. 기본 프로필에서는 이 정보를 압축 요약해서 보냅니다.
- **Packwise:**
  - AI 기능은 기본적으로 꺼져 있고, 외부 서버로 보낼 때는 **요청마다 확인**을 받습니다.
  - 채팅, 로그, 플레이어 이름, 서버 주소, 좌표, 시드, 인벤토리는 자동으로 수집하지 않습니다.
  - 보낼 내용(질문, 언어, 제한된 아이템·레시피 정보)을 **보내기 전에 미리보기**로 보여 줍니다.

**우리가 도입하면 좋은 이유**
- 지금 우리 모드는 자유 질문을 할 때 **인벤토리 요약(최대 40종)을 묻지 않고 Claude에 보냅니다.** 친구나 공개 저장소로 배포하면 사용자가 무엇이 나가는지 알 수 있어야 합니다.
- 비교한 AI 모드들이 모두 로컬 전용이거나 기본 off·요청마다 확인을 택했습니다. 사용자들이 이 부분에 민감하다는 신호입니다.
- 작업량이 적습니다. 설정 항목(`shareInventory` 등) 몇 개와 "처음 한 번 동의" 안내 정도면 되고, 나머지 기능에는 영향이 없습니다.
- **구현 방향:**
  - `ClientConfig`에 공유 항목 토글을 둡니다.
  - 처음 `/ai`를 쓸 때 보낼 정보가 무엇인지 채팅으로 안내하고 동의를 받습니다.
  - `/ai preview <질문>`으로 실제로 보낼 내용을 확인할 수 있게 합니다.

## 2. 도구 호출 방식 (LLM이 JEI 조회 도구를 직접 호출)

**원본 모드**
- [Viper LLM](https://modrinth.com/mod/viper-llm): Fabric 서버 전용, MC 1.21.1. 바닐라 클라이언트로도 쓸 수 있습니다.

**원본에서의 역할**
- 레시피 질문이 오면 LLM이 `@search_recipes`(대략적인 이름 검색, 모드 아이템 ID 지원), `@inventory` 같은 내장 도구를 **스스로 호출**해 실제 게임 데이터를 받아 온 뒤 답합니다.
- 채팅에는 도구 호출 과정이 보이지 않고 최종 답만 나옵니다.
- 작은 로컬 모델이 도구 호출 형식을 깨뜨리면 고쳐서 다시 시도합니다.

**우리가 도입하면 좋은 이유**
- 지금 우리 자유 질문 경로는 Claude가 **자기 기억만으로** 답합니다. 모드팩 설정으로 바뀐 레시피나 잘 모르는 모드에서는 틀린 레시피를 말할 수 있습니다. 사양서의 "계산은 코드, 판단은 AI" 원칙이 이 경로에서는 깨집니다.
- **Productive Bees 시나리오의 해결책입니다.**
  - "아이언 비"처럼 지금 검색 방식으로는 후보가 0개가 되는 질문이 있습니다.
  - 도구 호출 방식이면 Claude가 `search_items("Iron Bee")`처럼 검색어를 영어나 다른 표현으로 **바꿔 가며 다시 조회**할 수 있습니다.
- Claude API는 도구 사용(tool use)을 기본으로 지원합니다. 지금 `ClaudeProvider`를 대화가 오가는 반복 구조로 확장하면 됩니다.
- **구현 방향:**
  - 도구는 `search_items(query)`, `get_recipes(itemId)`, `get_inventory()`, `compute_missing(itemId, amount)` 네 가지로 시작합니다. 모두 지금 있는 `ItemCandidates`, `JeiRecipeSource`, `Items`, `CraftPlanner`를 감싸면 됩니다.
  - JEI 조회는 게임 스레드에서만 할 수 있습니다. 그래서 도구를 실행할 때마다 게임 스레드로 넘겼다가 결과를 다시 AI 스레드로 받아야 합니다.
  - 도구 결과는 MCAI처럼 압축 요약해서 토큰 사용량과 응답 시간을 줄입니다.
- **주의:** 호출 횟수가 늘어 비용과 응답 시간이 커집니다. 한 질문당 도구 호출 횟수에 상한을 둡니다.

## 3. 대체 재료 선택 + 레시피 선호 규칙

**원본 모드**
- [JEI unofficial](https://www.curseforge.com/minecraft/mc-mods/jei-unofficial): 공식 JEI와 무관한 포크. NeoForge 1.21.1, Forge 1.20.1

**원본에서의 역할**
- 여러 아이템이 들어갈 수 있는 입력 칸(태그, 대체 재료)에서 **마우스 휠로 하나를 고르면**, 그 선택이 생산 트리와 AE2 패턴에 그대로 반영됩니다.
- 트리 전개는 `config/jei/recipe-preferences.txt`의 사용자 규칙을 따릅니다. 우선순위는 즐겨찾기, 규칙, 현재 선택 순이라는 2차 출처가 있습니다.
- Shift+F로 전체 생산 트리를 만들고, 북마크한 레시피를 체인으로 묶어 배수를 바꾸면 총 재료가 다시 계산됩니다.

**우리가 도입하면 좋은 이유**
- 지금 `CraftPlanner`는 "인벤토리로 충족되는 칸이 많은 레시피, 같으면 JEI 순서"라는 고정 규칙만 씁니다. 플레이어가 "철은 제련 말고 Create 분쇄로"처럼 **원하는 경로를 지정할 방법이 없습니다.**
- 태그 칸은 항상 첫 번째 대체 아이템을 풀기 때문에, 의도와 다른 나무 판자나 금속을 기준으로 계산될 수 있습니다.
- 결과에 "어느 대안을 골랐는지"를 표시하면 사용자가 계산 결과를 믿고 고칠 수 있습니다.
- **구현 방향:**
  - `config/craftadvisor/recipe-preferences.txt`에 `아이템 → 선호 레시피 종류·재료` 규칙을 둡니다.
  - `CraftPlanner`가 고정 규칙보다 이 규칙을 먼저 적용하게 합니다. 순수 Java라서 단위 테스트를 바로 추가할 수 있습니다.
  - 아이템을 등록 ID로만 구분해서 변형이 합쳐지는 문제(`ItemKey`)도 이때 JEI 고유 ID 기준으로 함께 고칩니다.

## 4. 여러 목표를 하나의 목록으로

**원본 모드**
- [ETT – EMI Tree Tabs](https://www.curseforge.com/minecraft/mc-mods/ett-emi-tree-tabs): EMI 애드온. 최근 업데이트 2026-10-31. NeoForge 1.21.1 지원 여부는 확인이 필요합니다.

**원본에서의 역할**
- EMI 레시피 트리 여러 개를 **탭으로** 열어 두고, 이름과 색이 있는 단계(phase)로 묶습니다.
- 모든 트리에 걸쳐 중복을 합친 **크래프팅 목록 하나**를 만듭니다.
- 재고는 트리 사이에 **나눠 배정해서 두 번 세지 않습니다.** 예를 들어 두 트리가 각각 철 10개를 원하고 상자에 10개가 있으면 "10개 더 필요"로 나옵니다.
- 재료에 커서를 올리면 어느 트리가 얼마나 원하는지 보입니다.

**우리가 도입하면 좋은 이유**
- 공장을 지을 때는 기계 여러 개를 한꺼번에 준비합니다. 지금은 `/ai`를 두 번 하면 **각각 전체 인벤토리를 기준으로** 계산해서, 같은 철을 두 번 "있음"으로 셉니다.
- Create 클립보드가 페이지 단위라서 "목표별 단계(phase) = 클립보드 페이지"로 자연스럽게 연결됩니다.
- 계산기가 이미 인벤토리 사본을 쓰는 구조라서, **여러 목표를 하나의 공유 재고로 차례로 계산**하는 확장은 비교적 쉽습니다.
- **구현 방향:**
  - `/ai add <아이템>`으로 목표를 쌓고, `/ai list`로 합친 목록을 보고, `/ai clear`로 초기화합니다.
  - `CraftPlanner`에 여러 목표를 받는 함수를 추가하고 단위 테스트를 붙입니다.

## 5. AI 제공자 확장 (OpenAI 호환, Ollama, 오프라인)

**원본 모드**
- [PAIA (Pack AI Assistant)](https://www.curseforge.com/minecraft/mc-mods/pack-ai-assistant-paia): 클라이언트 전용. NeoForge 1.21.1판(0.2.1)은 개발 중단 상태이고, 새 기능은 Forge 1.19.2판에만 들어갑니다.

**원본에서의 역할**
- 특정 AI 제공자에 묶이지 않습니다. **OpenAI 호환 `/v1` 엔드포인트**, 로컬 **Ollama**, **오프라인 모드**(퀘스트와 로컬 정보만 사용, API 키 불필요)를 지원합니다.
- API 키와 base URL은 게임 안의 **Mods → Pack AI → Connection** 설정 화면에서 넣습니다.
- JEI의 실제 레시피·용도·기계 데이터와 퀘스트북을 근거로 답하고, 레시피 카드를 채팅에 출력합니다.

**우리가 도입하면 좋은 이유**
- 친구에게 공유하면 모두 Anthropic API 키를 따로 발급받아야 합니다. OpenAI 호환 API나 무료 로컬 모델(Ollama)을 지원하면 **AI를 쓸 수 있는 사람이 크게 늘어납니다.**
- 이 확장은 3라운드에서 요청하신 "확장성"이고, 이미 `AiProvider` 인터페이스로 자리를 만들어 두었습니다. `OpenAiCompatibleProvider`, `OllamaProvider` 구현과 설정 항목(`provider`, `baseUrl`)만 추가하면 됩니다.
- 오프라인 모드는 지금도 "키 없으면 계산과 클립보드만 동작"하는 형태로 일부 갖춰져 있습니다. 이를 명시적인 모드로 정리하면 됩니다.
- **주의:** 로컬 모델은 구조화 출력과 도구 호출이 불안정할 수 있습니다. Viper LLM처럼 형식 오류를 고치고 다시 시도하는 처리가 필요합니다.

## 6. 공장 비율 계산

**원본 모드**
- [GTCalcBoard (GregTech Calculator Board)](https://modrinth.com/mod/gtcalcboard) · [GitHub](https://github.com/Amvermain/GregTechCalculatorBoard): MIT 라이선스, 알파 버전. README는 1.20.1 Forge 기준이고 Modrinth 태그에는 NeoForge 1.21.1도 있어서, 1.21.1 지원은 확인이 필요합니다.

**원본에서의 역할**
- EMI, JEI, JEI++에서 레시피를 가져와 게임 안에서 **노드 그래프 흐름도**를 만듭니다.
- 비율 계산 기능:
  - 연결할 때 기계 대수를 **정수로 올림**해 맞춥니다.
  - **병목 기계를 기준으로** 상류 체인 규모를 역산합니다(Master Anchor 자동 스케일링).
  - **목표 출력률**을 맞추는 계산기가 있습니다.
- 필요한 기계와 멀티블록 부품을 **필요 물품 목록(BOM)**으로 합산해서 EMI 레시피 트리, JEI++, **클립보드**로 내보냅니다. README에 따르면 Create, Thermal, AE2도 다룹니다.

**우리가 도입하면 좋은 이유**
- 처음 요청하신 "공장 조언"의 핵심인데, 사양서에서 2차 버전으로 미뤄 둔 기능입니다.
- 결과를 클립보드로 내보내는 방식이 우리 Create 클립보드 기록과 같은 방향이라, 계산 결과를 "기계 N대 목록"으로 클립보드에 쓰는 형태로 이어 붙일 수 있습니다.
- 비율 계산은 결정적인 수학이라 **코드가 계산하고 AI는 설명만** 하는 우리 원칙과 잘 맞습니다.
- **어려운 이유:**
  - 기계마다 처리 시간이 필요한데, JEI는 레시피 처리 시간을 공통 방식으로 제공하지 않습니다.
  - Create는 회전 속도(RPM)에 따라 처리 속도가 달라집니다.
  - 그래서 처음에는 "Create 기계 몇 종만, 기본 RPM 기준"처럼 범위를 좁혀 시작하는 것을 권합니다.

## 7. 재료 이름 클릭으로 JEI 이동 + 인벤토리 강조

**원본 모드**
- [MCAI (MC Ai Intergration)](https://www.curseforge.com/minecraft/mc-mods/mcai-mc-ai-intergration)

**원본에서의 역할**
- 가지 모양 **레시피 트리 화면의 노드를 누르면** 해당 JEI 레시피가 열립니다.
- 추적 중인 레시피의 재료를 **인벤토리에서 색으로 강조**합니다.
- JEI가 있으면 추적 중인 레시피와 용도를 JEI에서 바로 엽니다.

**우리가 도입하면 좋은 이유**
- 지금 채팅의 부족 재료 목록은 읽기만 할 수 있습니다. 재료 이름을 누르면 그 재료의 JEI 레시피가 열리게 하면, **"다음엔 이걸 만들어야지"로 바로 이어집니다.**
- 작업량이 적습니다. 채팅 컴포넌트에 클릭 이벤트를 달고, 그 이벤트가 우리 클라이언트 명령(예: `/ai minecraft:iron_ingot`)을 실행하게 하면 됩니다. NeoForge는 클릭으로 실행된 클라이언트 명령도 서버로 보내지 않고 가로챕니다.
- **주의:** 클릭 이벤트는 **채팅에만** 답니다. Create 클립보드 항목에 클릭 이벤트가 있으면 서버가 클립보드 내용을 지워 버리기 때문입니다(`CreateClipboardWriter` 주석 참고).
- 인벤토리 강조는 화면 그리기 이벤트를 다뤄야 해서 클릭 기능보다 손이 더 갑니다. 클릭 기능을 먼저 하고, 강조는 나중에 합니다.
